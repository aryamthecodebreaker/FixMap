# FixMap v0.8.9 release notes

FixMap v0.8.9 is a reliability release for the CLI, scanner, ranking engine, MCP server, GitHub Action, evaluation harness, release workflows, documentation, and website.

## Highlights

- Type `/fixmap` with no task to open a complete, installed feature catalog covering Plan, Explain, Compare, Verify, Validate, Doctor, MCP, public issues, repository sources, task files, focus controls, working-tree mapping, cache control, outputs, test routing, risks, the GitHub Action, and setup.
- Use `--fail-on warning` in Verify or `fail-on: warning` in the Action when advisory findings must block CI.
- Scan and mention more source formats consistently, including PHP, Vue, Svelte, C#, CJS, and MTS; recognize C#, Java, PHP, and Ruby language/test conventions.
- Preserve ranking confidence when `--limit` changes by measuring clustering and contested leads over the full candidate list.
- Detect nested workspace lockfiles, diagnose conflicting root package managers, and route test commands to the correct tool.
- Read BOM-less UTF-16 task files, typographic quote pairs, Unicode task text, generator declarations, and stop-word-prefixed identifiers correctly.
- Keep the Action's comment, output, and step summary within GitHub size limits, including space already consumed by earlier steps.
- Harden validation, Markdown escaping, credential redaction, remote repository cleanup/ref selection, cache eviction, import-graph diagnostics, and package/server metadata gates.
- Make CI cross-platform, least-privilege, timeout-bounded, immutable-action pinned, non-mutating, and strict about all dependency audits and website lint warnings.
- Refresh external, held-out, adversarial, baseline, and savings evidence from the corrected scanner corpus.
- Replace the synthetic-looking website presentation with a restrained editorial product system, clearer proof, robust copy feedback, visibility-safe motion, complete metadata, and an honest interactive demo.

## Compatibility

- Node.js 20.11 or newer remains required.
- Existing `reportVersion: 1` consumers remain supported; additive fields can be ignored.
- Errors remain the default Verify failure threshold. Warning-level failure is opt-in.
- No hosted model, source upload, dependency installation, test execution, or package-script execution was added.

## Release evidence

The exact approved release commit must pass a clean `npm ci`, the complete local CI command, all recorded evaluation gates, both package dry-runs, fresh packed-package CLI/MCP/Core/Action smoke tests, and desktop/mobile website browser checks. After publishing, every public surface in the companion checklist must be verified against the same commit.
