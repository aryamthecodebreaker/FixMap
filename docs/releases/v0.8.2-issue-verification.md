# FixMap v0.8.2 issue verification ledger

This ledger accounts for the audit sweep filed against v0.8.1 on 2026-08-01 — issues #274
through #419. **The numbers below are the numbers this release publishes.** That is the
point of the document: v0.8.1's ledger recorded a held-out result the released artifacts
never carried (#333), so the ledger, the committed `results.json`, the README, the evidence
page, and the benchmark card must agree here or the release does not ship.

## What the suites measure, as recorded in this tree

| Suite | Top-1 | Top-3 | Top-5 |
| --- | --- | --- | --- |
| Held-out (12 repositories, never tuned against) | 7/12 · 58.3% | 8/12 · 66.7% | 9/12 · 75.0% |
| Development regression (16 repositories) | 11/16 · 68.8% | 16/16 · 100% | 16/16 · 100% |
| Adversarial (8 cases) | — | — | 8/8 pass, false-confidence rate 0.0 |

Confidence calibration on held-out, which **moved** in this release:

| Label | Cases | Correct | Accuracy |
| --- | ---: | ---: | ---: |
| high | 3 | 2 | 0.667 |
| medium | 7 | 4 | 0.571 |
| low | 2 | 1 | 0.50 |

The `high` band halved (6 cases → 3) and became more accurate (0.50 → 0.667), because
`scanComplete` now means "every candidate was actually read" rather than "the file limit was
not reached". A repository with files past the sample ceiling no longer earns a label it
cannot support. `high` outperforming `medium` is the ordering the label is supposed to have.

**8/12 Top-3 is not a regression against the 9/12 published before v0.8.1.** The held-out
composition changed during the v0.8.1 follow-up: `sindresorhus/got` rotated into the
regression suite once its blob permalink had informed a ranking fix, and a replacement was
drawn by the frozen selection rule. Different repositories, not a different ranker.

## Measured and rejected, not fixed

Recorded because a measured non-improvement is a result, and burying it is how a stale claim
starts.

- **#282 — tie-break on definition evidence.** Held-out Top-1 fell 7/12 → 6/12. It did not fix
  the jest case it was filed about, and it demoted mongoose's `lib/document.js` behind a helper
  that merely defines a matching symbol. Reverted; issue closed with the numbers.
- **#347 — `.css`/`.json` as source extensions.** The reported failure reproduces, but removing
  them measures as an exact no-op on both suites, because neither contains a case where an
  auxiliary file competes with implementation. Nothing shipped; the issue stays open.
- **#362 / #371 — generated-path mentions.** Two implementations were tried. Redirecting broke a
  test asserting that `"dist/x.js is stale"` is a task genuinely about the artifact; adding the
  source alongside left the artifact leading at `high`. Both reverted; the issues stay open.
- **#409 — import-graph direction labels.** Not a defect. Verified against a real graph: the
  label describes the neighbor's relation to the seed, deliberately the inverse of the map the
  edge came from. Swapping them would have reversed every proximity reason in every report. A
  regression test now pins the semantics.

## Validation record before publishing

- `npm run ci` green on the release commit: type-check, tests, production audit, lint, build,
  Action metadata, server manifest, Action bundle drift, smoke, internal evaluation, and the
  1,000-file scan benchmark.
- Held-out and regression suites re-recorded from this tree; `--check-recorded` passes for both,
  and `publish.yml` gates on both before the GitHub release is created.
- Adversarial suite: 8/8, false-confidence rate 0.0.
- Diagnostics that describe the checkout rather than the analysis are excluded from recorded
  benchmark evidence, because Windows and Linux check out webpack's longest fixture paths
  differently and a pinned benchmark must not vary by platform.
